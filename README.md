# TrollTrace

Исследовательский инструмент для отслеживания того, как нарративы из атрибутированных российских информационных сетей проникают в чешское информационное пространство: альтернативные медиа, Telegram-каналы, мейнстримные медиа и речь политиков, включая выступления в Палате депутатов.

Проект служит двум целям:
1. **Магистерская работа** по политологии (UJEP): узкий, защищаемый срез данных.
2. **Долгосрочный инструмент** (задел на PhD): широкая платформа мониторинга нарративов.

Разрабатывать нужно так, чтобы ядро закрывало потребности диплома, а расширения подключались модулями, не ломая ядро.

---

## 1. Исследовательский вопрос

**Основной вопрос:** проникают ли нарративы из атрибутированных российских сетей в чешские альтернативные каналы, мейнстримные медиа и парламентский дискурс, через каких акторов и с какой задержкой?

**Уточнение:** не «кто ведёт повестку», а «при каких условиях её ведёт тот или иной тип актора».

**Рабочие гипотезы:**
- **H1.** Новые, событийные нарративы впервые фиксируются в альтернативных каналах и доходят до парламента через популистов и гибридных акторов.
- **H2.** Устойчивые культурные нарративы (евро, евроскептицизм, однополые браки и т. п.) ведут сами политики, а каналы их подхватывают.
- **H3.** Мейнстримные медиа редко бывают первыми, но определяют, станет ли нарратив массовым.

**Теоретическая рамка:** intermedia agenda-setting, political agenda-setting (Walgrave & Van Aelst), hybrid media system (Chadwick).

**Важные ограничения формулировок:**
- Работа **описательная**, причинность не доказывается. Используем формулировку «впервые зафиксирован в корпусе», а не «возник здесь».
- **Собственной атрибуции нет.** Аккаунты и сайты не объявляются «российскими ботами» на основе нашего анализа. Атрибуция берётся только из внешних источников (госорганы, признанные исследовательские организации).
- **Собственного фактчекинга нет.** Посты не помечаются как «дезинформация». Допустимо: внешний рейтинг источника и ссылка на существующее опровержение на уровне карточки нарратива.

## 2. Слои данных (акторы)

| Слой | Что | Источник данных | Статус |
|---|---|---|---|
| **A. Атрибутированные сети** | Чешская версия сети Pravda / Portal Kombat | Сайты (RSS/sitemap), дашборд Check First | Ядро |
| **B. Альтернативные медиа** | Сайты из рейтингов вроде konspiratori.sk | RSS/sitemap | Ядро |
| **C. Telegram** | Альтернативные каналы + гибридные политики (напр. Райхл) | Telegram API (только публичные каналы) | Ядро |
| **D. Мейнстримные медиа** | ČT24, iROZHLAS, Seznam Zprávy, iDNES, Novinky, Blesk (+ ЧТК как событийная база) | RSS по рубрикам | Ядро |
| **E. Парламент** | Стенограммы Poslanecké sněmovny | Открытые данные psp.cz | Ядро |
| **F. Facebook / Instagram** | Страницы политиков и альтернативной сцены | Meta Content Library (только внутри защищённой среды) | Опционально, зависит от одобрения |
| **G. TikTok** | Политики, альтернативная сцена | TikTok Research API | Опционально, зависит от одобрения |
| **H. X** | Политики | DSA ст. 40 | Опционально, под вопросом |

**Принципы:**
- Каждая платформа — отдельный слой со своей нормализацией. Объёмы между платформами напрямую не сравниваются, сравниваются **траектории** (появление, задержка, пик).
- **Facebook не скрейпим.** Только легальные пути (Meta Content Library, DSA ст. 40). Если их нет, Facebook остаётся задокументированным ограничением.
- Для Meta действует модель «код идёт к данным»: разметка выполняется внутри защищённой среды, наружу выносятся только агрегаты. Архитектура должна поддерживать **импорт готовых агрегатов** без сырых текстов.

### Акторы
- **Политики:** институциональное определение — депутаты PSP, чешские евродепутаты, члены правительства, лидеры партий в период исследования.
- **Политические инфлюенсеры:** отдельная категория со своими критериями (охват), не смешиваются с политиками.
- **Гибридные акторы:** формально политики, по коммуникации ближе к альтернативной сцене. Отдельный флаг.
- Частота постов — **не критерий отбора**, а переменная для стратификации (терцили активности × партия × роль).
- Порог минимальной активности для включения фиксируется в конфиге и в методологии.

## 3. Нарративы и кодбук

**Тема ≠ нарратив.** «Евро» — тема, «евро разорит чехов» — нарратив. Каждая метка = **нарратив + позиция** (за / против / нейтрально).

Два слоя:
1. **Стабильная таксономия тем** (сверху).
2. **Живой реестр нарративов** (снизу):
   - **Дедуктивная часть:** кодбук из литературы и баз (EUvsDisinfo, Chapel Hill Expert Survey, литература о популизме и евроскептицизме).
   - **Индуктивная часть:** посты, плохо подходящие ко всем известным нарративам, складываются в корзину «unassigned», периодически кластеризуются (BERTopic или аналог). Плотные кластеры предлагаются как **кандидаты**. Решение о добавлении принимает исследователь, не модель.

**Формальные правила добавления нарратива** (параметры в конфиге): минимум N постов от минимум K независимых авторов за окно W.

**Версионность кодбука (обязательно):** у каждого нарратива есть ID, определение, примеры, дата добавления и история изменений. Любое изменение логируется.

**Ретроспективная разметка:** при добавлении нового нарратива весь архив прогоняется назад. Поэтому **полные тексты хранятся** (см. раздел 6).

**Метрики жизненного цикла нарратива:** первая фиксация (и в каком слое), пик, скорость затухания, порядок подхвата слоями и акторами.

## 4. Пайплайн обработки (воронка)

Тяжёлые модели не применяются ко всему корпусу.

1. **Сбор:** RSS/sitemap/API → сырые документы. Вежливый краулинг: паузы, robots.txt, user-agent исследовательского бота.
2. **Извлечение текста:** trafilatura для веб-страниц.
3. **Фильтр релевантности (дешёвый):**
   - на уровне подключения: только политические/зарубежные/экономические рубрики;
   - на уровне документа: ключевые слова + сходство эмбеддинга с описаниями нарративов.
   - Нерелевантное **не удаляется**: сохраняются метаданные (дата, рубрика, заголовок) как знаменатель для долей.
4. **Эмбеддинги:** локальная многоязычная модель (multilingual-e5 или LaBSE), считаются **один раз** при поступлении, хранятся в pgvector. Многоязычность важна: Pravda часто — машинный перевод с русского, и это позволяет связывать чешский текст с русским оригиналом без перевода.
5. **Детекция дословных заимствований:** шинглы (5–7 слов) + MinHash + LSH (datasketch). Без перебора всех пар.
6. **Детекция пересказов:** kNN-поиск по pgvector.
7. **Разметка нарративов:** классификатор/сходство с кодбуком на всём релевантном корпусе. LLM — только на отфильтрованных кандидатах (пары высокого сходства, кандидаты в новые нарративы, спорные случаи).
8. **Агрегация:** таблица `author × narrative × week` (число постов, доля, z-оценка). Обновляется инкрементально при каждом сборе.
9. **Валидация:** ручная разметка выборки (≈200+), согласие разметчиков (Krippendorff's alpha), сравнение с автоматикой (precision/recall). Отдельно — валидация детекции заимствований на вручную проверенных парах.

Транскрипция видео (Whisper локально) — опциональный модуль, в первую очередь для Telegram.

## 5. Нормализация

- Основная мера — **доля** постов автора о нарративе за период, не абсолютные числа.
- Дополнительно — **z-оценка относительно собственной истории** автора (детекция всплесков).
- **Предложение и спрос разделены:** что сказано (доля) и какой отклик получено (охват, реакции) — разные переменные, на одном графике не смешиваются.
- Агрегация по **неделям** по умолчанию; для редко пишущих — байесовское сглаживание.
- В UI рядом с долей всегда показывается **абсолютное число** (50% может быть одним постом).
- Знаменатель для медиа — все материалы политических рубрик за период.

## 6. Хранение и этика

- **Полные тексты хранятся** в закрытой исследовательской базе (нужны для ретроспективной разметки, валидации и защиты от исчезновения ссылок).
- **Публичный интерфейс** показывает только метки, короткую аннотацию и ссылку на оригинал. Полные тексты чужих статей не публикуются.
- Правовая основа: исключение для text and data mining в научных целях (ЕС, чешское авторское право). Тонкие места уточнить на факультете.
- Собираем только публичное: никаких обходов платного доступа, логинов, закрытых групп.
- **GDPR:** политики — публичные фигуры. Комментарии частных лиц не собираются; администраторы мелких каналов и прочие частные лица псевдонимизируются.
- Нужен план управления данными; уточнить требование этической комиссии UJEP.
- Пометок «дезинформация» на уровне постов и политиков нет (юридический и методологический риск).

## 7. Интерфейс

Приложение делится на две части: **рабочую** (анализ и просмотр) и **панель исследователя** (управление исследованием). Панель доступна только после входа.

### 7.1 Рабочая часть

**Дашборд:**
- **Список акторов** (фильтры: слой, партия, роль, когорта активности, флаг гибридности, поиск по имени). Клик по актору → график его нарративов во времени (доли по неделям).
- **Автоматическая разметка всплесков** относительно нормы актора.
- Tooltip: доля + абсолютное число.

**Режим сравнения (без ограничения числа линий):**
- График должен выдерживать **все активные акторы одновременно — до ~350 линий** по одному нарративу на общей оси времени, плюс группы (партия, все альтернативные каналы, весь мейнстрим, парламент).
- Технически: рендер на **canvas** (ECharts в canvas-режиме, не SVG), данные приходят готовыми из агрегатной таблицы одним запросом, анимации отключаются при большом числе серий. 350 серий × ~26 недель ≈ 9 тыс. точек — для canvas это нормальная нагрузка.
- Чтобы 350 линий читались, а не превращались в шум:
  - по умолчанию линии **тонкие и полупрозрачные**, цвет по слою или партии (а не уникальный цвет на актора);
  - **наведение на линию** подсвечивает её и приглушает остальные; имя актора видно в tooltip;
  - **поиск/выбор в легенде** закрепляет подсветку нескольких акторов поверх общего фона;
  - поверх фона можно включить **линии групп** (медиана/среднее по слою или партии) и полосу разброса (межквартильный размах);
  - легенда при большом числе серий — с прокруткой и поиском, а не плоский список.
- **Альтернативный вид для массового сравнения — тепловая карта** «актор × неделя» (цвет = доля нарратива), с сортировкой по времени первой фиксации, слою или партии. Для 350 акторов это часто читается лучше линий: сразу видно, кто и когда подхватил нарратив. Переключатель «линии / тепловая карта» в режиме сравнения.

**Клик по точке графика → реальные посты/статьи за ней:**
- Работает напрямую, если на графике **до N линий** (N в настройках, по умолчанию 10).
- При большем числе линий клик по фону не открывает посты (иначе каша). Сначала нужно **выбрать/закрепить конкретную линию** (наведение + клик по линии или выбор в легенде), и только тогда клик по её точке открывает посты этого актора.
- В тепловой карте клик по ячейке однозначен (один актор × одна неделя) и работает всегда.

**Прочее:**
- **Карточка нарратива:** определение, версия, дата добавления, первая фиксация, слои по порядку появления, ссылки на внешние опровержения (Demagog.cz, Manipulátoři, AFP Fakty, EUvsDisinfo) при наличии.
- **Просмотр заимствований:** пары текстов с высоким сходством и подсвеченными совпадающими фрагментами.

Графики строятся **из агрегатной таблицы**, не из сырых постов.

### 7.2 Панель исследователя

Отдельный раздел для управления исследованием. Все действия в нём пишутся в **журнал аудита** (кто, когда, что изменил, старое и новое значение) — это часть воспроизводимости для методологии.

**Страница «Акторы»** — динамическое добавление и удаление акторов:
- Добавление вручную (форма) и **массовый импорт из CSV** (например, список депутатов).
- Поля: имя, тип, слой, партия, роль, флаг гибридности, привязанные источники/аккаунты (URL, handle Telegram и т. п.), основание включения (критерий, ссылка).
- **Валидация и защита от дублей:** проверка, что аккаунт или URL ещё не привязан к другому актору; проверка доступности источника при добавлении.
- **Безопасное удаление = архивация, а не удаление из БД.** Актор получает статус «исключён» с датой и причиной. Его документы, метки и история остаются в базе, сбор новых данных останавливается, на графиках он по умолчанию скрыт (но может быть показан фильтром).
- **Периоды включения:** у актора хранится, с какой по какую дату он входил в выборку. Повторное включение открывает новый период, а не затирает старый. Агрегаты и доли считаются с учётом этих периодов, чтобы исключение актора не искажало знаменатели задним числом.
- Добавление актора ставит в очередь задачу **ретроспективного сбора** (насколько позволяет источник) и пересчёта агрегатов.
- Перед необратимыми действиями (если их вообще разрешать) — подтверждение и предпросмотр последствий: сколько документов и меток затронуто.

**Страница «Кандидаты в нарративы»** — очередь на ручное решение:
- Карточка кандидата: автоматически сгенерированное описание кластера, ключевые слова, примеры постов, число постов и **независимых авторов**, окно времени, слои, в которых он появился, ближайшие существующие нарративы по сходству.
- Индикатор, проходит ли кандидат **формальные правила добавления** (N постов / K авторов / окно W).
- Действия: **принять** (создать нарратив с определением и позицией), **объединить** с существующим нарративом, **отклонить** (с причиной), **отложить** (вернётся при росте кластера).
- Принятие запускает **ретроспективную разметку** архива и пересчёт агрегатов; кодбук получает новую версию.
- Отклонённые и объединённые кандидаты не исчезают: история решений хранится для методологии.

**Уведомления:**
- Новые кандидаты в нарративы; резкие всплески у акторов; ошибки сбора (источник недоступен, RSS пуст N дней, сменилась структура сайта); завершение долгих задач (ретроразметка, пересчёт).
- Лента уведомлений в панели + опционально e-mail или Telegram-бот.

**Прочие страницы панели:**
- **Кодбук:** редактирование тем и нарративов, история версий, сравнение версий.
- **Источники:** список подключённых сайтов/каналов/лент, статус сбора, последняя успешная загрузка, объём за период.
- **Настройки:** пороги (релевантность, сходство, правила добавления нарратива, минимальная активность актора, N для клика по точке), окно агрегации, модели. Изменение настроек тоже версионируется.
- **Валидация:** интерфейс ручной разметки выборки и расчёт согласия.
- **Задачи:** статус фоновых процессов (сбор, эмбеддинги, ретроразметка, пересчёт агрегатов).
- **Журнал аудита.**

**Доступ:** роли минимум «исследователь» (полный доступ к панели) и «наблюдатель» (только рабочая часть, например для руководителя). Публичная версия, если будет, — только рабочая часть без полных текстов.

## 8. Стек

- Backend: Python, Django
- БД: PostgreSQL + pgvector
- Графики: ECharts или Plotly
- Тексты: trafilatura
- Эмбеддинги: multilingual-e5 / LaBSE (локально)
- Заимствования: datasketch (MinHash/LSH)
- Индуктивные темы: BERTopic
- Планировщик сбора: Celery/cron (на выбор)
- Опционально: Whisper (транскрипция), LLM API только для отфильтрованных кандидатов

## 9. Модель данных (черновик)

- `Source` — площадка/сайт/канал: тип слоя, платформа, атрибуция (кем, ссылка на отчёт), внешний рейтинг.
- `Actor` — автор: тип (политик / инфлюенсер / медиа / канал / атрибутированная сеть), партия, роль, флаг гибридности, когорта активности, статус (активен / исключён), основание включения.
- `ActorInclusionPeriod` — периоды, когда актор входил в выборку (с/по, причина включения/исключения).
- `ActorAccount` — привязка актора к источникам и аккаунтам (уникальность аккаунта на уровне БД).
- `Document` — пост/статья/выступление: актор, источник, время, URL, заголовок, полный текст, рубрика, флаг релевантности, метрики отклика, хэш, эмбеддинг (pgvector), MinHash-подпись.
- `Topic` — стабильная тема.
- `Narrative` — нарратив: тема, определение, примеры, статус (кандидат/активный/архив), даты.
- `NarrativeVersion` — история изменений кодбука.
- `Label` — документ × нарратив × позиция, источник метки (модель/человек), уверенность, версия кодбука.
- `ReuseLink` — пара документов: тип (дословно/пересказ/репост/цитата), сходство, подтверждено ли вручную.
- `WeeklyAggregate` — актор (или группа) × нарратив × неделя: n, доля, z, отклик.
- `Debunk` — нарратив × внешнее опровержение (организация, URL).
- `NarrativeCandidate` — кандидат в нарративы: кластер, примеры, метрики, статус (новый / принят / объединён / отклонён / отложен), решение, причина, кто и когда решил.
- `Notification` — уведомление для исследователя: тип, объект, текст, прочитано ли.
- `Setting` / `SettingVersion` — настройки исследования (пороги, окна, модели) с историей изменений.
- `AuditLog` — журнал всех действий в панели исследователя.
- `Job` — фоновые задачи (сбор, ретроразметка, пересчёт агрегатов) и их статус.

## 10. Скоуп и порядок разработки

**MVP для диплома:**
1. Сбор: Pravda (CZ), 2–3 альтернативных сайта, 10–20 Telegram-каналов, мейнстрим по политическим рубрикам, стенограммы PSP.
2. Кодбук на **3–5 нарративов** + позиция.
3. Эмбеддинги + MinHash, детекция заимствований Pravda → остальные слои.
4. Агрегатная таблица + дашборд с графиком актора и режимом сравнения (масштабируемым до всех акторов, включая тепловую карту).
5. Панель исследователя: управление акторами (архивация, периоды включения), источники, настройки, журнал аудита.
6. Валидационный модуль для ручной разметки.
7. Период около полугода; 2–3 детальных кейса с цепочками (включая гибридных акторов).

**Расширения (после MVP):** индуктивное обнаружение нарративов, импорт агрегатов из Meta, TikTok, транскрипция видео, полный список политиков со стратификацией, корреляции со сдвигом / Granger / Hawkes.

**Сбор запускать как можно раньше:** RSS не даёт архива назад.
